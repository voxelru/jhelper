# Мок Jira на CSV

Минимальный REST-сервис, который отвечает как Jira, а данные берёт из
`issues.csv`. Нужен, чтобы отлаживать jhelper без настоящей Jira.

## Запуск

```bash
python jira_mock/server.py
```

В `.env` приложения:

```
JIRA_BASE_URL=http://127.0.0.1:8089
JIRA_USERNAME=any
JIRA_PASSWORD=any
```

Логин и пароль не проверяются. Переменные мока: `MOCK_JIRA_PORT` (8089),
`MOCK_JIRA_HOST` (127.0.0.1), `MOCK_JIRA_CSV` (путь к другому CSV).

## CSV

Строка — задача, колонка — поле. Файл перечитывается на каждый запрос:
поправили, сохранили, обновили доску. Разделитель `,` или `;`, кодировка
UTF-8 или cp1251 (как сохраняет Excel) определяются сами.

| Колонка | Что это | В ответе Jira |
|---|---|---|
| `key` | ключ задачи; строки без ключа пропускаются | `key` |
| `summary` | название | `fields.summary` |
| `issuetype`, `status`, `priority` | названия | `fields.<поле>.name` |
| `assignee` | логин; пусто — без исполнителя | `fields.assignee.name` / `.key` |
| `assignee_name` | отображаемое имя | `fields.assignee.displayName` |
| `original_estimate`, `remaining_estimate` | `3d`, `1d 4h`, `90m`, `2w`; число без единицы — минуты | `fields.timetracking.*` |
| `labels` | метки через пробел | `fields.labels` (список) |
| любая другая | имя колонки = ID поля (`duedate`, `customfield_10100`, …) | `fields.<колонка>` |

В произвольных колонках пустая ячейка — `null`, число — число, остальное —
строка. Если нужно значение сложной формы, в ячейку можно положить JSON:
`{"value": "ООО Ромашка"}` или `[{"name": "Спринт 12", "state": "active"}]`.

Необязательная колонка `status_category` (`To Do` / `In Progress` / `Done`)
задаёт категорию статуса явно. Без неё категория угадывается по названию:
«Готово», «Закрыта», `Done`, `Resolved` — Done; «В работе», `In Progress` —
In Progress; всё остальное — To Do.

ID произвольных колонок должны быть указаны в `config/app_settings.yaml` —
иначе приложение их не читает и **не сохраняет** (даты при сохранении
пропускаются с пометкой «не задан jira_field_id»). Для `issues.csv` из примера
они уже прописаны:

```yaml
fields:
  customer:   {jira_field_id: customfield_10100}
  sprint:     {jira_field_id: customfield_10007}
  start_date: {jira_field_id: customfield_10015}
  end_date:   {jira_field_id: duedate}
```

## Запросы

Все пути доступны и как `/rest/api/2/...`, и как `/rest/api/3/...`.

| Запрос | Поведение |
|---|---|
| `GET`, `POST /search` | поиск по JQL; `startAt`, `maxResults`, `fields` |
| `GET /issue/{key}` | одна задача |
| `POST /issue` | создать задачу: нужны `project.key` и `summary`; ключ выдаётся следующий по проекту |
| `PUT /issue/{key}` | записать поля (`fields`) и операции (`update`) |
| `DELETE /issue/{key}` | удалить строку |
| `PUT /issue/{key}/assignee` | сменить исполнителя; `{"name": null}` — снять |
| `GET`, `POST /issue/{key}/transitions` | список статусов и смена статуса |
| `GET /myself` | пользователь из Basic Auth |
| `GET /user/search`, `/user/assignable/search` | исполнители из CSV, фильтр `username` / `query` |
| `GET /field` | список полей и колонок — удобно подсматривать ID |
| `GET /priority`, `/status`, `/issuetype`, `/project` | значения, встречающиеся в CSV |
| `GET /serverInfo` | заглушка версии |

`PUT` принимает `assignee`, `timetracking`, `labels`, `summary`, `priority`,
`issuetype` и поля, для которых в CSV есть колонка. В `update` понимаются
`set` для любого поля и `add` / `remove` для меток. Статус меняется только
через `transitions`, как в Jira.

## JQL

```
assignee is not EMPTY AND statusCategory != Done ORDER BY priority DESC
assignee = currentUser() OR labels in (frontend, bug) ORDER BY key DESC
project = DEMO AND duedate >= 2026-10-20 AND cf[10100] ~ "вектор"
```

- **Операторы:** `=`, `!=`, `~`, `!~`, `>`, `>=`, `<`, `<=`, `[NOT] IN (...)`,
  `IS [NOT] EMPTY`, `AND`, `OR`, `NOT`, скобки, `ORDER BY` по нескольким полям.
- **Поля:** `key`, `project`, `summary`, `assignee` (логин или имя), `status`,
  `statusCategory`, `priority`, `issuetype` / `type`, `labels` и любая колонка
  CSV — по имени или как `cf[10100]`.
- **Функции:** `currentUser()`, `now()`.
- **Как в Jira:** `!=` и `NOT IN` не находят задачи с пустым полем; приоритеты
  сравниваются по рангу (`priority > Medium`), а не по алфавиту.
- **Не поддерживается:** `WAS`, `CHANGED`, прочие функции (`startOfDay()`,
  `openSprints()` …), относительные даты (`-1d`), поиск по названию кастомного
  поля (`"Story Points"`). На такой запрос мок отвечает 400 с текстом ошибки.

## Что стоит знать

- **Это не вся Jira.** Реализовано то, что нужно для отладки доски и
  соседних сценариев. Нет комментариев, ворклогов, вложений, связей, спринтов
  и досок Agile API, прав доступа, истории изменений и вебхуков.
- **Авторизация не проверяется** — подходит любой логин и пароль.
- **Любая запись переписывает `issues.csv`.** Файл окажется изменённым в git;
  если это мешает, укажите свой файл через `MOCK_JIRA_CSV`.
- **После правки кода мока его нужно перезапустить** — CSV перечитывается сам,
  а `server.py` и `jql.py` нет.
- **Запись в поле без колонки** возвращает 400 в формате Jira
  (`Field '…' cannot be set`) — так удобно ловить неверный `jira_field_id`.
- **Оценки при записи нормализуются:** приложение шлёт `720m`, в файле будет
  `1d 4h`.
- **Тип задачи отдаётся только названием, без id.** Переопределения в
  `issue_types` по id на моке не сработают, по названию — сработают.
- **При смене исполнителя** отображаемое имя берётся у другой задачи с тем же
  логином; если такой нет, в `assignee_name` пишется сам логин.
- **Переходы статусов не ограничены:** из любого статуса можно перейти в любой,
  который встречается в CSV.

## Что внутри

- `server.py` — сам сервис на Flask, новых зависимостей нет.
- `jql.py` — разбор и выполнение подмножества JQL.
- `issues.csv` — 307 демо-задач: 10 сотрудников, 5 спринтов, 6 бизнес-партнёров,
  оценки от 2 часов до 5 дней; часть задач без дат, спринта или партнёра.

## Как проверялось

На копии проекта подняты мок и приложение, затем через API приложения
выполнено то же, что делает доска: перенос задачи (даты и трудозатраты) и
смена исполнителя, после — «Сохранить в Jira». Все четыре поля записались в
CSV. Отдельно проверены JQL-запросы из раздела выше, ошибки 400 на
неподдерживаемый JQL, создание, удаление, смена статуса, операции с метками и
справочные запросы. Мышью в браузере доска не проверялась.
